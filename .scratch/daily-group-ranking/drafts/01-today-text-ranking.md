# 01: 群内“谁最能聊”当日文本排行榜

**What to build:** 群成员真正 @当前机器人并发送“谁最能聊”后，机器人查询当前群当天已保存的文本，回复发言最多的 5 位成员。没有数据或查询失败时返回简短提示。本任务完成后可以独立使用，不依赖话题分析或模型服务。

**Blocked by:** None (can start immediately).

**Status:** draft

## Acceptance criteria

- [ ] 仅在允许交互的当前微信群、真正 @机器人且规范化正文 `strip()` 后等于“谁最能聊”时执行；不依赖机器人昵称匹配，不接受斜杠、别名或参数。未匹配消息沿用原流程；匹配后包括异常情况均不回落普通 LLM 对话。
- [ ] 请求开始时固定进程本地日期和截止时间，仅统计当天零点至截止时间的当前账号、当前群记录，不增加时区配置或其他时间范围。
- [ ] 仅计入 `type == 1`、正文非空白的有效入站文本；排除机器人自己、撤回、删除、无效身份或时间的记录，以及本功能指令；按 Native 消息 ID 去重。
- [ ] 按完整 senderId 分组，按条数降序、senderId 升序排序，展示 Top 5 或实际人数，同名成员不合并。尽力解析 Top 5 的群昵称／显示名，失败时使用可区分的 ID 简写；显示名去换行并截断，不主动 @上榜成员，不为昵称遍历全群。
- [ ] 复用 Native 本地历史分页，每页最多 50 条、最多 20 页、查询总时限 15 秒；按 nextCursor 继续，重复游标停止；只有确认时间倒序时才按昨天的记录提前结束。
- [ ] 达到查询上限或读取部分页面后失败时保留已有排行，末尾仅补充“本次为部分统计。”；正常榜单不附数据来源或“仅供娱乐”尾注。
- [ ] 空结果统一回复“今天暂无可统计的聊天消息。”；第一页即失败或超时回复“暂时查不到群聊记录，请稍后再试。”。
- [ ] 复用当前群白名单、群回复开关、LoopGuard、事件与发送状态检查；熔断或来源失效时静默退出。同一触发事件只查询并回复一次，发送结果未知时不自动重发；完整结果一次发送为纯文本，不经过普通 LLM 分段或转图流程。
- [ ] 使用现有 read/send 凭据，不依赖历史工具、微信修改工具或群聊摘要开关；不新增配置、依赖、Function Tool、数据库表或聊天正文持久化。
- [ ] 仅覆盖 SPEC 中 4 类相关核心测试：触发、混合记录统计、空结果／查询失败、单条回复／重复事件。共享权限、熔断和媒体复用已有测试，只有修改共享逻辑时才运行对应用例；定向静态检查和测试通过。
