# SPEC — 谁最能聊

**Project:** `astrbot-plugin-wechat-native`  
**Target:** v0.3.6 / agent-wechat-native v1.5.1  
**Priority:** P2  
**Type:** Group Command

## 1. 目标

新增一个手动触发的微信群聊指令，展示当天已保存文本消息中发言最多的 5 位成员，
并尽力提取最多 3 个热门话题，附上一句轻松的点评。

本期只处理文本，保持实现简单，不增加配置项、外部服务或数据库表。

## 2. 触发方式

在当前群真正 @机器人，并发送：

> @机器人实际名称 谁最能聊

`机器人实际名称` 为占位，用户通过微信选择并真正 @当前机器人；代码不依赖昵称文字匹配。

- 只处理 `WeChatNativeEvent` 群消息，并遵守群白名单、群回复开关和 LoopGuard。
- 使用原始 mentions 元数据确认真正 @机器人，不能只检查合成的 `At` 组件或手打的 @文字。
- 去掉现有流程识别的机器人 @前缀后，对正文执行 `strip()`，必须等于 `谁最能聊`。
- 不接受 `/` 前缀、别名、参数和其他时间范围。
- 匹配成功后由本功能独占处理，包括查询失败和空结果；不再进入普通 LLM 对话。
- 未匹配的消息继续沿用现有处理规则。

优先复用现有命令机制。若无法保证无斜杠和精确匹配，则在插件现有消息入口增加轻量路由，
不修改 AstrBot 全局命令解析。

## 3. 统计规则

### 3.1 统计范围

- 只查询触发事件所属的当前账号、当前群。
- “今天”使用插件运行进程的本地日期，采用服务器／容器现有时区，不增加时区配置。
- 在请求开始时确定当天日期和截止时间，统计当天零点至该截止时间的已保存消息。
- 不实现跨时区切换、历史日期或自定义时间范围。

### 3.2 计数口径

一条满足以下条件的 Native 消息计为一次发言：

- `type == 1`，即文本消息，且 `body` 为非空白字符串。
- `direction == "incoming"`，发送者 ID 有效且不是机器人自己。
- 属于当前账号、当前群，消息时间属于本次统计范围。
- 没有撤回或删除标记。

其他消息不计数，包括图片、语音、视频、文件、表情、系统消息、引用消息卡片及其内嵌文字。
缺少有效消息 ID、发送者 ID 或时间的记录直接跳过，不推测身份和日期。
本功能的指令消息不参与排行或话题分析。

- 按 Native 消息 ID 去重。
- 按完整 `senderId` 分组，同名成员不合并。
- 按发言条数降序排列，数量相同时按 `senderId` 升序排列。
- 只展示前 5 人，不足 5 人时展示实际人数。
- 优先使用群昵称，其次显示名；名称不可用时显示可区分的 senderId 简写。
- 仅为 Top 5 尽力解析名称，不为补全昵称遍历整个群名单；名称查询失败不影响排行。
- 显示名称去掉换行并适当截断，避免破坏结果布局；榜单不主动 @上榜成员。

没有可统计的消息时，直接回复：

> 今天暂无可统计的聊天消息。

不额外区分全天无人发言、只有非文本消息或本地没有保存记录等情况。

## 4. 历史查询与上限

复用 `NativeClient.messages()` 查询 Native 本地已保存的群消息。

- 每页最多 50 条，最多读取 20 页，历史查询总时间不超过 15 秒。
- 按 `nextCursor` 继续分页；没有下一页时结束，遇到重复游标时停止。
- 当天日期在本地过滤。只有确认接口按时间从新到旧返回时，才可在越过当天范围后提前停止。
- 到达页数或时间上限时，保留已读取结果并标记“部分统计”。
- 已成功读取部分页面后，后续页面查询失败，同样返回部分统计。
- 第一页即查询失败或超时，回复“暂时查不到群聊记录，请稍后再试。”。
- 没有有效消息时统一回复空结果文案，不再细分原因。
- 正常结果不附加数据来源说明或“仅供娱乐”等尾注；统计仍基于 Native 当天已保存的文本。

查询范围始终由可信事件确定，不允许模型指定账号、群或查询范围。
不改变现有 SSE 游标、已读状态或消息正文存储策略。

## 5. 热门话题与点评

### 5.1 热门话题

热门话题为附加功能，不影响排行榜返回。

- 只使用本次已获取、符合统计条件的文本。
- 按时间排序后，最多均匀抽取 100 条，每条最多 200 个字符。
- 不向模型传入成员姓名、senderId、群 ID、消息 ID 或排行榜数字；仅传必要的文本样本。
- 少于 5 条有效文本时不调用模型，显示“今天还没有聊出明显的话题”。
- 使用当前会话配置的 AstrBot LLM，单独请求一次，不附带日常对话历史，不开放工具。
- 话题分析超时上限为 8 秒，不重试，不因分析失败追加第二条微信消息。
- 要求返回话题字符串数组；代码只接受最多 3 个非空、去重后的话题，每项最多 20 个字符。
- 模型明确返回空数组时，显示“今天还没有聊出明显的话题”。
- Provider 不可用、超时、异常或输出无法解析时，省略话题与点评，只返回排行榜。
- 将样本作为待分析数据，不执行其中的指令；不把样本文字提升为系统指令。

排行榜人数、姓名和统计数字始终由代码计算和格式化，不使用模型生成的排行。

### 5.2 趣味点评

只在成功得到至少一个话题时显示点评，使用预定义模板，不额外调用 LLM。

例如：

> {第一名}今天聊得最起劲！从{话题一}聊起，话匣子就没关上。

文案保持轻松，不贬低成员，不推断成员性格或私人情况。
机器人名称和成员名称只用于显示，不承担身份判断。
点评标题使用当前机器人可用的显示名称；无法获取时使用“机器人点评”，不写死具体昵称。

## 6. 回复示例

最终通过现有发送链路，一次发送完整的纯文本结果，不进入普通 LLM 回复的分段或转图流程。
榜单序号和标题使用普通文字，不依赖微信渲染 Markdown。

```text
谁最能聊

1. 潜水冠军：68 条
2. 干饭队长：45 条
3. 夜猫子：32 条
4. 咕咕精：21 条
5. 奶茶续命：13 条

今日热门话题

1. 周末聚餐
2. 最近在玩的游戏
3. 通勤路上的歌单

{机器人显示名称}点评

潜水冠军今天聊得最起劲！从周末聚餐聊起，话匣子就没关上。
```

达到查询上限或中途查询失败时，仅在末尾补充：

> 本次为部分统计。

没有足够文本或没有明显话题时，话题部分显示固定提示，省略点评。
模型分析失败时省略话题、点评两个部分，不影响榜单。

## 7. 工程实现

建议新增 `group_ranking.py`，负责有界历史查询、文本过滤、计数、样本准备和结果格式化。

`main.py` 只负责识别指令、调用统计、调用已有 Provider 提取话题，并通过现有链路发送结果。

复用：

- `WeChatNativeEvent` 的身份与当前群上下文。
- `NativeClient.messages()` 和现有群成员资料查询能力。
- 当前会话的 AstrBot LLM Provider。
- 现有消息状态、发送回执和撤回检查处理重复事件及不确定的发送结果。
- LoopGuard 处理循环熔断；不能将其当作事件去重机制。

该显式群命令不依赖 `enable_history_tools`、`enable_wechat_actions` 或 `enable_group_summary` 开关，
使用已有 read/send 凭据，仍遵守当前群的交互权限。

查询记录和话题样本仅在本次请求内使用，不新增正文持久化、定时任务或统计缓存。
不新增 Function Tool、依赖、配置项或数据库表。

## 8. 异常与重复处理

- LoopGuard 已熔断、群不在白名单或群回复关闭时，静默退出。
- 同一触发消息只执行一次，不因重复事件重复查询、调用模型或发送结果。
- 触发消息已撤回或事件失效时，沿用现有检查取消回复。
- 发送结果未知时沿用现有状态标记，不自动生成新请求重发。
- 只记录必要的错误类别和查询状态，不记录聊天正文、模型样本、Token 或完整异常响应。
- 对用户只返回本 SPEC 中的简短提示，不暴露堆栈和内部配置。

## 9. 测试与验收

新增测试集中在 `tests/test_group_ranking.py`，仅覆盖 5 类核心场景：

1. **触发**：群内真正 @机器人并精确发送“谁最能聊”时执行；私聊、未 @和错误指令不执行。
2. **统计**：用一组混合记录验证当天文本计数、Top 5 和并列排序；昨天、非文本、自身、撤回和重复消息不计数，同名成员不合并。
3. **无数据与查询失败**：空记录返回无数据提示，查询失败返回友好提示。
4. **话题降级**：模型正常时展示话题；模型不可用时仍返回正确排行榜。
5. **单条回复**：重复事件不重复执行或发送，匹配指令后不产生额外普通 LLM 回复。

白名单、LoopGuard、发送回执和媒体等复用现有测试覆盖；修改共享逻辑时再运行受影响的已有用例。

实现完成后运行本次改动的检查：

```sh
ruff check main.py group_ranking.py tests/test_group_ranking.py
pytest -q tests/test_group_ranking.py
```

真实微信群验收：真正 @机器人发送 `谁最能聊`，只收到一条结果。
有数据时展示最多 5 位文本发言者；模型可用且存在明显话题时展示最多 3 个话题。
没有数据、只有少量文本或模型不可用时，按本 SPEC 简单降级即可。

## 10. 非目标

- 非文本消息、语音转写或引用卡片内容统计。
- 历史日期、自定义时间范围、跨群排名或复杂时区处理。
- 完整微信历史恢复、长期统计库或聊天正文归档。
- 排行榜管理页、每日推送、积分、签到或奖励。
