# 群聊摘要

用户已要求实现群聊摘要。本次在当前工作区完成手动触发版本。

## 行为

- 机器人参数增加 `enable_group_summary`，默认关闭；开启后在内存缓存允许群的实时收到的文本，普通消息仍遵守现有回复规则。
- 群内真正 @机器人并发送 `总结群聊` 或 `群聊摘要` 生成摘要；仅该群记录进入请求，私聊及其他平台不处理此命令。
- 默认每群最近 200 条、最近 60 分钟，可配置 1–500 条及 1–1440 分钟。仅缓存开启后收到的消息，不读取历史；重启及停止清空。
- 全部群合计最多 2000 条；每条最多缓存 1000 字符，模型输入记录最多 24000 字符，超限取最新记录，说明范围及截断。
- 不缓存本人发送、非文本、历史、过旧、重复、撤回消息或摘要命令；群白名单和 disabled 模式同样约束缓存。
- 采用该 AstrBot 会话配置的聊天模型，独立请求，不注入日常对话历史或开放工具。输出讨论要点、已确认结论、待办及未解决问题；不得虚构负责人或期限。
- 无记录、模型不可用、超时、正在生成时返回明确提示。生成中被撤回/淘汰的来源记录不能继续发出摘要；发送沿用现有去重及撤回复查。

## Approaches

1. 调用 Native 历史接口：可能补足启动前消息，但需要额外 API 能力和历史范围策略，不适合这次的实时接入范围。
2. 内存缓存 + 独立模型请求（本次采用）：复用实时消息和 AstrBot 模型，限制数据量，不改变持久化状态库；代价是重启后没有旧上下文。
3. 正文持久化与定时摘要：可跨重启及定时推送，但扩大数据存储和调度范围，留待后续需求。

## 约束与验证

沿用 Python 3.12、AstrBot 4.29.3，无新增依赖。验证使用现有 AstrBot 安装、模拟 Native HTTP 和模型响应，不使用真实微信凭据或模型费用。摘要质量与真实微信收发需要部署后验证。
